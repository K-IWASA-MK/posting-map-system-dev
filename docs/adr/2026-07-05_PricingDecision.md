# Decision Log: Pricing Model & Unit Definition

**Date**: 2026-07-05  
**Author**: 岩佐CEO / AI品質管理部  
**Status**: Decided

---

## 1. 決定事項 (Decision)
アカウント数（人数）によるサブスクリプション課金モデルは採用せず、管理対象となる**「データ量（配布ユニット数）」に基づく従量・個別見積もりモデル**を採用する。また、配布ユニットは必要以上に細分化せず「市区町村 ──> 次住所階層」までとする。

## 2. 理由 (Rationale)
* **現場のボランティア活用を最大化**: 人数課金にすると、決裁者が追加料金を嫌い「一時的な配布員やボランティア」のアカウント登録を躊躇する。これはデータ収集量を最大化したいというプラットフォームの目的と矛盾する。
* **ビジネス規模との連動**: 管理する配布エリアの広さ（ユニット数）は、その政党支部や陣営の活動規模および予算規模（支払能力）にほぼ正比例するため、価格提案の合理性が高い。
* **データ構造のシンプル化**: 丁目や番地、世帯単位で細分化しすぎると、データベースやAPIの通信量（GAS API制限）に悪影響を与え、かつ高齢の配布員が画面操作で迷う原因になる。

## 3. 採用案 (Alternative Selected)
* **販売仕様**: 初期10万円＋月額3万円〜。販売資料には「データ量に応じて個別見積もり」と記載。
* **内部仕様**: 基本単位を市区町村から次の住所階層まで（例：芝公園）とし、内部的な見積もり基準として「500配布ユニット」を基本ラインとする。

## 4. 却下案 (Alternative Rejected)
* アカウント数（アクティブ配布員数）に応じた人数課金。
* 丁目・番地・各世帯などの極小単位での地図ユニット課金。

## 5. 将来見直す条件 (Review Criteria)
* 500ユニット未満の小規模な自治体であっても、アクティブ配布員数が数百人規模になり、API通信費やサーバー負荷だけが異常に高騰し、現行の月額3万円モデルでは赤字になることが判明した場合。
