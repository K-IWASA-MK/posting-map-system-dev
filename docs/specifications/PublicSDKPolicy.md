# 公開 SDK 露出ポリシー (Public SDK Policy)

## 概要
本仕様書は、AIOS プラットフォームが外部（アプリケーション層およびサードパーティ開発者）に提供する SDK API の露出基準、ドキュメント要件、および互換性ポリシーを定義します。

## SDK 露出の基本方針
- **必要最小限の露出 (Minimum Exposure)**:
  - デフォルトではすべてのクラス、メソッド、インターフェースを非公開（パッケージプライベートまたはインターナル）とします。
  - アプリケーション開発に必要な必要不可欠なインターフェースのみを、意図的に SDK パッケージ（`sdk/` 配下）のエクスポート定義を通じて公開します。
- **カプセル化の保護 (Encapsulation Guard)**:
  - 公開APIは、内部のデータ構造やランタイム状態を直接呼び出し元に露出させてはなりません。パラメータや戻り値には、必ず専用のデータ転送オブジェクト (DTO) またはイミュータブルなインターフェースを使用します。

## API 安定性レベル (API Stability Tiers)
すべての SDK 公開 API は、ドキュメントおよびコードコメント内に以下のいずれかの安定性レベルを明記する必要があります。

| 安定性レベル | 説明 | 互換性保証 |
| :--- | :--- | :--- |
| **Stable (安定版)** | 本番環境で安全に使用できる十分に検証されたAPI。 | メジャーバージョンアップ（SemVer）を除き、破壊的変更は行われません。 |
| **Experimental (実験版)** | 新機能のプレビューや検証目的で提供される一時的なAPI。 | マイナーまたはパッチバージョンであっても、事前予告なく変更または削除される可能性があります。 |
| **Deprecated (非推奨)** | 将来的に削除が予定されている旧式API。 | 削除されるまでの間は機能維持されますが、代替となる推奨APIの使用が強く推奨されます。 |

## 破壊的変更と移行プロセス
1. **非推奨化 (Deprecation Announcement)**:
   - 変更対象のAPIは、まず `@deprecated` タグを付与し、代替となる新APIへの移行方法をドキュメントに明記してリリースします。
2. **削除の猶予期間 (Grace Period)**:
   - 非推奨化されたAPIは、最低1回のマイナーリリースサイクル以上の猶予期間を経て、次のメジャーバージョンアップ時に初めて削除が実行されます。
3. **マイグレーションガイドの提供**:
   - 破壊的変更を伴うリリースでは、自動コード修正ツール（Codemodなど）または詳細なステップバイステップのマイグレーションガイドを同梱しなければなりません。
