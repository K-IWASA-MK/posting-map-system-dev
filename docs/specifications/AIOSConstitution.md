# AIOS 憲章 (AIOS Constitution)

## 概要
本憲章は、AIOS プラットフォームを構築・維持するための14の正式原則を定義します。プラットフォームの設計、実装、リファクタリングに関わるすべての決定は、本原則に従わなければなりません。

## 14の正式原則

### 1. ドメイン非依存 (Domain Independent)
AIOS Core は、いかなる特定のアプリケーションドメインからも完全に独立していなければなりません。業務プロセス、顧客固有の概念、特定のアプリ画面やデータスキーマに関連するロジックや用語の混入を徹底的に排除します。

### 2. 基盤最優先 (Foundation First)
新機能の追加よりも、システムの健全性、アーキテクチャの整合性、および安定検証（Verification）のパスを最優先します。

### 3. 設計図専用 (Blueprint Only)
プラットフォーム層はインターフェース、プロトコル、ライフサイクルの定義（設計図）に専念し、具体的な実装はプラグインやケイパビリティ層で動的に結合する設計とします。

### 4. イベント駆動 (Event Driven)
コンポーネント間の通信は、原則として非同期またはイベント駆動のメッセージング（`RuntimeEventBus` 等）を介して行い、結合度を最小限に抑えます。

### 5. 不変元帳 (Immutable Ledger)
システム内の状態遷移や重要なアクションは、すべて追跡可能かつ改ざん不可能な「不変元帳（`RuntimeLedger`）」へ追記（Append-Only）されなければなりません。

### 6. 射影原則 (Projection Principle)
任意の時点の状態は、不変元帳に記録されたイベント履歴を再生（Replay）して算出される読み取り専用の状態表示（Projection）として表現されます。

### 7. プラグインファースト (Plugin First)
新機能や拡張モジュールは、コアへの直接編集ではなく、プラグインインターフェースに準拠した独立モジュールとして実装・導入します。

### 8. SDKファースト (SDK First)
すべてのアプリケーションは、AIOS が提供する公開SDKを通じてのみプラットフォームの機能を利用できます。カーネルやランタイム内部への直接アクセスは禁止します。

### 9. 公開API専用 (Public API Only)
SDKから露出されるAPIは、明示的に定義された公開API表面のみとし、ランタイム内部のクラスや状態はすべて隠蔽（カプセル化）されます。

### 10. デフォルトセキュリティ (Security by Default)
最小権限の原則（Least Privilege）に基づき、デフォルトですべての操作境界に認証・認可およびデータ保護の機構を適用します。

### 11. 監査可能性 (Auditability)
すべてのコード実行、認証状態、エラー履歴は、デバッグおよびセキュリティ監査のために標準化されたログ形式で追跡可能でなければなりません。

### 12. 確定的実行 (Deterministic Execution)
同一の元帳イベントと同一の環境パラメーターが与えられた場合、ランタイムの実行結果は常に同一（決定論的）でなければなりません。

### 13. ステートレスランタイム (Stateless Runtime)
実行ランタイムエンジン自体は永続的なミュータブル状態を持たず、状態の永続化および取得はすべて元帳または外部ストレージエンジンを介して行います。

### 14. 後方互換性 (Backward Compatibility)
SDKの公開APIは、原則として後方互換性を維持します。破壊的変更が不可避な場合は、厳格なバージョンアップポリシーと移行パスを提供しなければなりません。
