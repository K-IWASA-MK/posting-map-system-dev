# AIOS Data Dictionary Specification (共通データモデル・用語定義規範)

Version: 1.0.0
Phase: Phase 110 (Data Dictionary Foundation)
Status: Active

---

## 1. 目的 (Purpose)
本仕様書は、AIOS (Artificial Intelligence Operating System) における情報の表記ゆれを防ぎ、すべてのレジストリ、ログ、およびデータモデル間での整合性とトレーサビリティを機械的に保証するため、システム全体で使用される共通データ定義、識別子、状態遷移、重大度レベル、予約語、および用語集を一元定義する **Single Source of Truth (単一の真実のソース)** となります。

---

## 2. 共通識別子仕様 (Common Identifier Specification)

AIOS を構成する各オブジェクトの一意なIDは、以下の命名規則（フォーマット）を完全に順守して定義されます。一度採番されたID（例: `INC-2026-0001`）は、対象レコードが更新されても変更されません（Stable IDs Policy）。

* **Rule ID (監査ルールID)**:
  * フォーマット: `[カテゴリ大文字3文字]-[連番3桁]`
  * 例: `CLI-001`, `JSN-001`, `DOC-001`, `DEV-001`, `AUD-001`
* **Incident ID (例外・インシデントID)**:
  * フォーマット: `INC-[西暦4桁]-[連番4桁]`
  * 例: `INC-2026-0001`
* **History ID (不変監査履歴ID)**:
  * フォーマット: `HIS-[西暦4桁]-[連番4桁]`
  * 例: `HIS-2026-0001`
* **Knowledge ID (統合ナレッジID)**:
  * フォーマット: `KB-[西暦4桁]-[連番4桁]`
  * 例: `KB-2026-0001`
* **Decision ID (意思決定判定ID)**:
  * フォーマット: `DEC-[西暦4桁]-[連番4桁]`
  * 例: `DEC-2026-0001`
* **Audit ID (個別監査セッションID)**:
  * フォーマット: `AUD-[西暦4桁]-[連番4桁]`
  * 例: `AUD-2026-0001`
* **Review ID (個別レビューセッションID)**:
  * フォーマット: `REV-[西暦4桁]-[連番4桁]`
  * 例: `REV-2026-0001`
* **Phase ID (開発フェーズ識別ID)**:
  * フォーマット: `PHASE-[フェーズ番号3桁]`
  * 例: `PHASE-110`, `PHASE-101`

## 3. AI エージェント識別子 (AI Agent Identifier)
監査、レビュー、および意思決定レコード等で、「誰が判定または実行したか（Actor / Reviewer）」を統一記録するための標準コード値です。

* **`FLASH`**: 迅速な初期ビルド検証や、計画書を伴わないセルフチェックを行う軽量AIエージェント。
* **`GEMINI_PRO`**: 詳細なコード適合度検証、依存関係の追跡などを行う中核推論AIエージェント。
* **`OPUS`**: アーキテクチャ統制、不変データの整合性確認、および全体監査を行う最上位AIエージェント。
* **`HUMAN`**: 人間管理者 (岩佐CEO等) による手動レビュー。
* **`SYSTEM`**: CI/CDパイプライン、Git Hook、ビルド自動化機構などの実行システム。

## 4. 状態・レベル列挙型 (Enumerations)

### 4.1 共通状態 (Common Status Enumeration)
すべてのオブジェクトライフサイクルを表現するための標準状態値です。

* `Proposed`: 新規オブジェクトが提案・設計中である初期状態。
* `Waiting Review`: 査読・レビューを申請し、承認を待っている状態。
* `Approved`: レビュアーによる承認が完了した状態。
* `Active`: 監査や実行プロセスにおいて現在有効・稼働中である状態。
* `Completed`: 当該タスクまたはフェーズが完了し、検証をパスした状態。
* `Verified`: 不変な履歴整合性チェック等をパスし、結果が保証された状態。
* `Deprecated`: 代替の出現等により将来廃止予定であり、非推奨となった状態。
* `Archived`: 参照のみ（Read-Only）可能な過去履歴として保管された状態。

### 4.2 共通重大度 (Common Severity Enumeration)
インシデントや規約違反の重大度スケールです。

* `Critical`: システム全体の動作または重大な設計原則に違反する致命的レベル（プロセス強制遮断対象）。
* `Major`: 主要機能または規約に違反する重大レベル。
* `Minor`: 部分的な不整合または副次的な機能への影響がある中・軽微レベル。
* `Warning`: ドキュメント記述漏れや軽微な不一致（警告メッセージの提示対象）。
* `Information`: 警告を伴わない単なる動作ガイダンスや統計ログ。

### 4.3 共通意思決定 (Common Decision Enumeration)
 Preventive Gate または人間レビューによる承認判定結果です。

* `GO`: 実装または次のフェーズへの移行を許可。
* `NO-GO`: 却下。直ちに変更を破棄し、再設計を要求。
* `Review Required`: 自動判定では合否が確定せず、人間の追加査読を要求。
* `Deferred`: 判断を保留し、後日の追加情報または別フェーズでの解決に回す。

### 4.4 共通レビュー結果 (Review Result Enumeration)
各AIエージェントまたは人間による検証セッションの合否評価値です。

* `PASS`: すべてのルールおよびテストに適合。
* `PASS_WITH_COMMENT`: 適合しているが、将来の改善に向けた注記あり。
* `WARNING`: 適合しているが、一部ルールに適合しない潜在的リスクあり（要修正推奨）。
* `FAIL`: 規約違反またはビルド例外を検出し、不適合。
* `BLOCKED`: 致命的な例外が発生し、検証の続行が不可能な状態。

### 4.5 共通確信度 (Common Confidence Level)
ナレッジやルール評価の信頼性の度合いです。

* `High`: 100%の再現性または客観的検証が確立している。
* `Medium`: 一定の検証は完了しているが、エッジケースにおける再現性が未確定。
* `Low`: 暫定的な知見であり、再現頻度が不明確。
* `Unknown`: 信頼性が未検証。

## 5. 共通メタデータフィールド (Common Metadata Fields)
すべての AIOS レジストリ JSON に含まれる標準フィールドのプロパティ定義です。

| フィールド名 | 型 | 説明 |
|---|---|---|
| `id` | String | 本仕様書第2節で規定された一意な識別ID。 |
| `title` | String | オブジェクトの簡潔な名称・要約。 |
| `description` | String | 詳細な説明または動作要件。 |
| `status` | Enum | 本仕様書第4.1節で規定された共通状態。 |
| `version` | String | セマンティックバージョン表記（例: `1.0.0`）。 |
| `owner` | String | 保守または実行責任主体。 |
| `reviewer` | String | 承認判断を下したレビュアー名または Agent ID。 |
| `created_at` | DateTime | 生成日時（ISO-8601 UTC形式）。 |
| `updated_at` | DateTime | 最終更新日時（ISO-8601 UTC形式）。 |
| `phase` | String | 発生または対象となったフェーズID（例: `PHASE-110`）。 |
| `references` | List[String] | 関連仕様書、コードファイル、またはバグチケット等のリンク。 |
| `metadata` | Dictionary | 拡張用メタデータ領域（フリー辞書）。 |

## 6. 共通日付・日時表現 (Common Timestamp Policy)
すべてのタイムスタンプは、以下の形式に従って統一して記述されなければなりません。

* **規格**: **ISO-8601**
* **タイムゾーン**: **UTC (協定世界時)**
* **表記形式**: `YYYY-MM-DDTHH:MM:SSZ`
* **例**: `2026-07-01T12:34:56Z`

## 7. 命名規約 (Naming Convention)

* **PascalCase**:
  * クラス名、インターフェース名、DTOクラス名、共通列挙型（Enum）名。
  * *例*: `MilestoneAudit`, `CommonStatus`
* **snake_case**:
  * 変数名、関数名、メソッド名、JSONキー、Pythonソースファイル名。
  * *例*: `incident_registry.json`, `created_at`, `get_summary()`
* **kebab-case**:
  * コミットメッセージのプレフィックス、CLIのサブコマンド名、ドキュメントのMarkdownファイル名。
  * *例*: `docs/specifications/preventive-gate.md`, `runtime-execution-milestone-audit`

## 8. 予約語ポリシー (Reserved Words)

* **`Context`**:
  * **ポリシー**: **DTO内部、シリアライズ定義、および独自変数名において、原則使用禁止**。
  * **理由**: 外部の依存コンテキストとの混同を招くため。代替語として `Runtime` または `Definition` を使用すること。
* **`Runtime`**:
  * **ポリシー**: 実行時に動的にコンパイル、実行、またはシリアライズされるオブジェクト・クラス名に付与。
* **`Blueprint`**:
  * **ポリシー**: 実行不可能であり、仕様、設計定義、または構造スキーマを記述するデータオブジェクトにのみ付与。
* **`Metadata`**:
  * **ポリシー**: DTO内の拡張情報および属性管理領域に付与。
* **`History`**:
  * **ポリシー**: 改ざん不可能な、不変（Immutable）の監査履歴ログの定義に付与。
* **`Knowledge`**:
  * **ポリシー**: 履歴やインシデントから得られた教訓や再利用可能知見の記述オブジェクトに付与。

## 9. 用語集 (Glossary)

* **Audit (監査)**:
  コードやプロセスが、規約や設計原則に適合しているかを客観的なエビデンスに基づき検証する行為。
* **Incident (例外・インシデント)**:
  開発または運用中に検知された、不整合、ビルド例外、テスト失敗、および監査違反。
* **Knowledge (ナレッジ)**:
  インシデントのRCAから得られた、再利用可能なベストプラクティスや教訓。
* **Rule (監査ルール)**:
  適合性を評価するための、検証手順と合格基準を明文化した規約。
* **Review (査読・レビュー)**:
  人間またはAIエージェントが、計画や成果物を評価して承認を検討する行為。
* **Advisory (アドバイザリ)**:
  予防ゲートウェイが出力する、開発をブロックしない推奨事項および警告。
* **Preventive Gate (事前予防ゲート)**:
  実装前に、過去の障害やルール違反を自動チェックし、リスク評価を行う関門。
* **Blueprint (ブループリント)**:
  ランタイム実行コードを含まない、仕様や設計の記述定義。
* **Runtime (ランタイム)**:
  CIE Platformの稼働時に動的に動作し、処理を実行するコードやオブジェクト。
* **Foundation (ファウンデーション)**:
  各フェーズが具現化コードに進む前に、整合した仕様を確立させるための基盤設計段階。
* **Future Automation (将来の自動化)**:
  本仕様に基づき、将来実行コードがデータ定義ファイルを自動ロード・バリデーションする際のロードマップ。
