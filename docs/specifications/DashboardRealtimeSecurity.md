# Dashboard Real-time Security Specification (DashboardRealtimeSecurity.md)

## 1. 重複排除と Replay アタック防止 (Event Idempotency)
ネットワーク再接続時のストリームの巻き戻りや、悪意ある第三者による古いイベントデータの再送（Replay アタック）を防ぐため、受信データの重複排除を行う。
- **Event ID ストア**:
  `DashboardRealtimeAdapter` 内に、過去 10 分間に処理された `eventId` の履歴ストア（最大 1000 件のメモリ内Set/FIFO配列）を保持する。
- **重複破棄判定**:
  新規イベントの `eventId` がストアに既に存在する場合は、重複処理とみなし、即座に破棄（DROP）してログ警告のみをコンソールに出力する。

---

## 2. タイムスタンプ検証 (Timestamp Validation)
システムの正常な時系列の観測を維持するため、端末時刻とイベント時刻の妥当性評価を行う。
- **評価基準**:
  受信したイベントの `timestamp` が、クライアント側の現在ローカル時刻（UTC）と比較して、以下の範囲を逸脱している場合は不正とみなして破棄する。
  * **古すぎるイベント**: 現在より `5分` 以上過去のイベント。
  * **未来すぎるイベント**: クライアントの時計の誤差を考慮し、現在より `1分` 以上未来のイベント。

---

## 3. Read-Only 運用の絶対保証 (Receiver-Only Stream)
ダッシュボードは「カーネルの実行状態の表示・観測」のみを行う。
- **双方向通信の禁止**:
  WebSocket 等の双方向通信チャネルを使用した場合、クライアントからの入力ハンドリングや、意図しないコマンド（承認・実行指令）送信の脆弱性が発生するリスクがある。そのため、受信専用の一方向通信である **Server-Sent Events (EventSource)** を通信経路に限定し、ブラウザからカーネルへの書き込み（Write）や制御用 API の直叩きを構造上完全に不可能にする。
- **データ不変の保護**:
  受信したイベントペイロードは、アダプターによる論理メッセージへの正規化マッピングのみを行い、UI レンダラーに渡す過程でデータを動的に書き換えたり、不要な状態書き戻し（逆流）を引き起こさないように設計する。
