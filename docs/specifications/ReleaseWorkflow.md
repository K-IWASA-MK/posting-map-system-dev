# リリースワークフロー (Release Workflow)

## 概要
本仕様書は、AIOS プラットフォームにおけるバージョン管理、リリースチャネル、Git タグの運用、およびデプロイメントプロセスを定義します。

## セマンティックバージョニング (Semantic Versioning 2.0.0)
AIOS は、`MAJOR.MINOR.PATCH` の形式に基づく厳格なセマンティックバージョニングを運用します。

- **MAJOR**: APIの破壊的変更（後方互換性のない変更）が行われた場合にインクリメントします。
- **MINOR**: 後方互換性を維持したままでの新機能の追加、またはプラットフォーム構造の拡張が行われた場合にインクリメントします。
- **PATCH**: 後方互換性を維持したバグ修正やパフォーマンス改善が行われた場合にインクリメントします。
- **プレリリース識別子**: 開発版やリリース候補（RC）には、`-alpha.X` や `-beta.X` などの識別子を付加します。（例: `v6.0.0-alpha.1`）

## リリースチャネル (Release Channels)

### 1. 開発リリース (Development Release)
- **対象**: スプリント中の開発成果や実験的機能。
- **バージョン**: `vX.Y.Z-alpha.N` または `vX.Y.Z-beta.N`
- **デプロイ先**: 開発環境 / Staging API（LINE LIFF デバッグ環境等）。
- **デプロイ手段**: 開発リモート (`origin-dev`) へのプッシュおよび、開発用 GAS デプロイの更新。

### 2. 安定版リリース (Stable Release)
- **対象**: Quality Gate を完全に通過し、実機検証（QA）が完了したビルド。
- **バージョン**: プレリリース識別子のない正式バージョン（例: `v6.0.0`）
- **デプロイ先**: 本番環境。
- **プロセス**: 本部および岩佐CEOの最終承認を得て、`main` ブランチへのマージと本番環境への clasp デプロイを実行します。

### 3. ホットフィックスリリース (Hotfix Release)
- **対象**: 本番環境で検出された緊急性の高い重大なバグの修正。
- **バージョン**: PATCHバージョンのインクリメント（例: `v6.0.1`）
- **プロセス**: 安定版タグまたは `main` ブランチから直接 `hotfix/` ブランチを切り、検証合格後、即座に本番へ適用および `main` への差し戻しマージを行います。

## Git タグの運用
リリース時には、以下のルールで Git タグを付与します。
- **タグ名**: 必ず小文字の `v` から開始するセマンティックバージョン（例: `v6.0.0`, `v6.0.0-alpha.1`）。
- **タグの作成タイミング**: リリースビルドの生成および動作検証が完全に PASS し、Git Push の準備が整った段階。

## リリースノートの作成
リリースごとに、`RELEASE_NOTES.md` または `CHANGELOG.md` を以下の標準的なフォーマットで更新します。

```markdown
# Release vX.Y.Z (YYYY-MM-DD)

##  追加機能 (Added)
- ○○機能の追加

## ⚙️ 変更・改善 (Changed)
- ○○モジュールの最適化

## 修正 (Fixed)
- ○○バグの修正

## 🚨 破壊的変更・互換性情報 (Breaking Changes)
- 移行に必要なアクション
```
