# Dashboard Severity Model Specification (DashboardSeverityModel.md)

## 1. 重要度レベルの定義とUIマッピング (Severity Levels & UI Mapping)
ダッシュボード上の視覚的ノイズを抑え、管理者が瞬時に優先状況を把握するため、イベントの重要度を 3 段階のレベル（CRITICAL / WARNING / INFO）にマッピングし、表示用アラートレベルへと静的に変換する。

| 重要度レベル (Severity) | 定義基準 | UI表示用レベル (UI Level) |
|---|---|---|
| **CRITICAL** | カーネル初期化失敗、隔離境界の突破など、システム稼働を阻害する重大アラート | `danger` |
| **WARNING** | ガバナンスルール違反、品質検証ゲートの不合格など、注意を要する状態遷移 | `warning` |
| **INFO** | 正常な品質ゲート合格、シミュレーション起動、通常動作の生存信号など | `success` / `info` |

---

## 2. Event Payload 不変性の保証 (Event Payload Immutability)
`DashboardSeverityMapper` は、重要度の判定結果をメタデータとしてイベントオブジェクトに付与するのみであり、受信した元イベントの `eventId`、`timestamp`、`payload`（データ本体）の中身を書き換え、改変、または削除することは一切禁止する。
受信したままのデータをそのまま UI に伝播・表示し、ダッシュボードを中立的な観測装置として稼働させる。

---

## 3. 分析ロジックおよび状態書込みの禁止
- **静的変換の徹底**:
  「現在のエラー率がしきい値を超えているか」「過去数分間に特定のイベントが何回連続したか」等の分析処理や複合評価ロジックをマッパー内に持ち込むことは禁止する。イベントタイプに紐づく静的な辞書マッピングのみで判定し、分析処理はカーネル（バックエンド）の責務とする。
- **ガバナンス変更の排除**:
  重要度判定結果に基づいて、他のコンポーネントの状態（Status）を直接変更するなどの状態書込み（Mutation）は一切行わない。
