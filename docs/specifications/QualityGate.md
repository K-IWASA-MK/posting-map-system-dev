# 品質ゲート基準書 (Quality Gate)

## 概要
本仕様書は、AIOS プラットフォーム開発におけるコードおよびドキュメントの品質基準（Quality Gate）を定義します。本品質ゲートは、変更がリリース可能な品質であることを保証するための「防波堤」として機能します。

## 品質検証対象と合格基準 (Verification Items & Passing Criteria)
品質ゲートは、以下の7つの領域を自動的および手動で検証します。

### 1. Build (ビルド)
- **検証方法**: TypeScript/JavaScript コンパイラによる静的検証。
- **合格基準**: コンパイルエラーおよび警告がゼロであること（`tsc --noEmit` の PASS）。

### 2. Test (テスト)
- **検証方法**: 単体テスト（Unit Test）および結合テスト（Integration Test）の実行。
- **合格基準**: すべてのテストケースが成功し、カバレッジ基準（必要に応じて）を満たしていること。

### 3. Architecture (アーキテクチャ)
- **検証方法**: `tools/architecture-check.ts` 等による階層構造チェック。
- **合格基準**: 上位レイヤーから下位レイヤーへの一方向の依存が完全に守られており、逆流や不正な参照がないこと。

### 4. Dependency (依存関係)
- **検証方法**: パッケージ依存チェッカーによる依存グラフの静的解析。
- **合格基準**: 外部ライブラリや内部モジュール間で、未定義または循環する依存関係（Circular Dependency）が存在しないこと。

### 5. SDK Boundary (SDK 境界)
- **検証方法**: API 露出チェッカーによる検証。
- **合格基準**: アプリケーション層からプラットフォームの非公開内部モジュール（`core/`, `runtime/` 等の直接参照）へのアクセス試行がないこと。

### 6. Security (セキュリティ)
- **検証方法**: 静的コードセキュリティスキャンおよびスキーマ検証。
- **合格基準**: 入力データの検証（Schema Validation）が行われており、ハードコードされた認証情報やセキュリティ脆弱性がないこと。

### 7. Documentation (ドキュメント)
- **検証方法**: レビュー時のチェックリスト検証。
- **合格基準**: 公開APIに対するコメントやドキュメントが完全に記述されており、`HANDOVER.md` や `RELEASE_NOTES.md` に不足がないこと。

## 品質検証の運用方法
- **ローカル検証**: 開発エージェントは、コミット前に `npm run quality:check` をローカル環境で手動実行し、全項目の合格を確認します。
- **ゲート不合格時の対応**: 1つでも合格基準を満たさない項目がある場合、そのコミットまたはプッシュは無効（Block）と判定され、修正が行われるまで次のプロセスへ進むことはできません。
