# Dashboard Design & UX Guide

Version: 1.0
Last Updated: 2026-07-05

---

## 1. Dashboard UX Principles (ユーザー体験原則)

DashboardのUX設計における絶対的な共通原則です。すべてのデザインとコンポーネント配置は、以下の原則に従わなければなりません。

1. **3秒で状況が伝わる。**
   画面を開いた瞬間、または切り替えた瞬間に、全体の活動進捗やボトルネックが直感的に脳へ入るビジュアル設計を徹底します。
2. **スクロール量を最小化する。**
   画面遷移や過度な縦スクロールを避け、基本的に1画面（ファーストビュー）で主要なデータが完結するレイアウトを採用します。
3. **数字よりグラフを優先する。**
   細かいテーブルデータや数字の羅列を見るのではなく、進捗比率や推移をグラフ・ビジュアルとして捉えられるようにします。
4. **タップ数を最小化する。**
   見たい情報に到達するまでの操作回数（フィルタ選択やドリルダウン）を最小化（原則3クリック以内）します。
5. **Google Sheetsを感じさせない。**
   スプレッドシート特有の無骨なテーブル表示やセルのようなUI表現を完全に排除し、洗練されたネイティブSaaSとしての外観を提供します。
6. **管理画面ではなく「魅せる画面」である。**
   業務的なデータ入力や複雑な設定操作のための画面ではありません。支部長が自身の活動成果を実感し、他支部長や外部の意思決定者（候補者等）にデモをして価値を伝えるためのショーケースです。
7. **PCで見た瞬間に活動状況が理解できる。**
   現場でスマホ片手に活動する配布員とは対照的に、PCの前に座る管理者がワンアクションで全体のオペレーション状況を俯瞰できるUIにします。

## 2. グラフルール (Visual Graph Rules)

* **「3秒ルール」の順守**:
  * グラフの種類は「棒グラフ」「円グラフ」「エリア進捗マップ」に絞り、複雑な複合グラフは使用しません。
  * 凡例や目盛り線などの非本質的な要素は極限まで省略または薄く表示し、主要な進捗データが最も際立つようにします。
* **対比と進捗の強調**:
  * 目標値に対する現在値（達成率%）を明確に比較できるビジュアルを中央に配置します。

## 3. カラー＆テーマルール (Color & Theme System)

確定デザインシステムに従い、以下の配色を厳格に守ります。

| レイヤー | 色・スタイル | 用途 |
|---|---|---|
| **Layer 1** | `#000000` (純黒) | ページ全体の背景 |
| **Layer 2** | `#1C1C1E` (ダークグレー) | すべてのカード・ヘッダーの固定背景 |
| **Special** | `Liquid Glass` (透過度8%白 + blur: 20px) | ナビゲーションバーやフローティング要素 |
| **Accent Blue**| `#2563eb` (アクセントブルー) | 主要な進捗バー、ボタン、アクティブ状態 |
| **Accent Green**| `#22c55e` (アクセントグリーン) | 完了ステータス、数値上昇、カウンター |

* **光彩（発光）の制御**: 
  過剰なサイバー感を避け、ガラスのフチやボーダーの背後にわずかなグロー（`rgba(37,99,235,0.03)`）を忍ばせることで、静かで重厚な高級感を演出します。

## 4. モーション＆アニメーションルール (Motion Rules)

* **ロード・トランジション**:
  * グラフの描画やデータの反映時には、スムーズなフェードイン（`opacity: 0` -> `1`）およびスケールアップ（`0.98` -> `1`）を適用します。
  * 変化のアニメーション時間は **200ms〜400ms** とし、イージング関数には `ease-out` を優先してキビキビとした操作感を持たせます。
* **ローディング時の配慮**:
  * データ取得中に一瞬画面が真っ白になったり、レイアウトがガクついたり（レイアウトシフト）しないよう、固定サイズのプレースホルダーやスケルトンスクリーンを適用します。

---

## 5. デバイスの役割分担 (Device Boundary)

* **スマホアプリ (POSTING MAP)**: 
  データ発生源 (Data Creator)。現場で歩きながら、簡単なタップ操作（配布完了、チラシ受け取り等）を行うことのみに特化し、分析や集計の表示は一切行いません。
* **支部・県連Dashboard (PC)**:
  データ可視化 (Data Showcase)。スマホから送信された生データをアグリゲーションし、マップ上に配布軌跡を描画、目標達成率をグラフでダイナミックに可視化します。

## 6. ダッシュボード共通Hover UX・インタラクションルール (Dashboard Hover UX Specification)

### 6.1 グラフの通常時とHover時の対比
通常時の画面の主役は、無駄なグリッドや数値のない「滑らかなグラフ曲線」です。
ユーザーが特定の日付やエリアの詳細を確認したいと感じた瞬間（Hover）にのみ、極上のGlass Tooltipが現れ、データポイントが `#EA5F08` で上品に発光（Glow）します。

* **折れ線グラフ表示項目**:
  * 日付
  * 活動人数 (人)
  * 新規活動人数 (人)
  * 配布枚数 (枚)
  * 保管者数 (人)
* **棒グラフ表示項目**:
  * 市町村名
  * 保有枚数 (枚)
  * 保管者 (人)

### 6.2 アニメーションの基本仕様
* **Tooltip表示時 (Fade In)**: 200ms〜250ms のイージングをかけてスッと浮かび上がらせる。
* **Tooltip非表示時 (Fade Out)**: 150ms で滑らかに消去する。
* **データポイントの発光 (Active Point Glow)**: 半径を拡大しつつ、250ms でアウターグロー（影のブラー効果）を適用する。
* すべての描画処理は `will-change: transform, opacity` 等の最適化を行い、カクつき（フレームドロップ）を一切発生させないこと。
