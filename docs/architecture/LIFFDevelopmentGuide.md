## 1. 実際に発生した問題とトラブルシューティング (Incidents & Troubleshooting)

本プロジェクトのLINE LIFF開発および実機テストにおいて、実際に発生した重要インシデントと、その原因・対策・再発防止策です。

### 1.1 ID画面真っ黒問題 (ID Card Blank Screen Incident)
* **事象**: モバイル実機のLIFF上で「設定画面（公式配布員IDカード）」を開くと、画面全体が真っ黒になり何も表示されない、またはIDカードの一部が切れて表示される。
* **原因**:
  * iOS/AndroidなどのモバイルWebViewにおいて、画面上部ヘッダーやボトムナビの高さ計算が崩れ、画面領域外にコンテンツが押し出された。
  * `h-[100dvh]` や `h-screen` の解釈がOSやWebViewのツールバー有無で異なり、コンテナの高さがはみ出しスクロール不可に陥った。
* **対策**:
  * 画面全体のスクロールを無効化する代わりに、IDカードの配置コンテナに対して `justify-start pt-10 pb-6` のようにパディングによる静的マージンで垂直位置を完全に固定した。
  * `translate-y` などの動的シフトによる座標操作を廃止し、パディングによる対称マージンを適用した。
* **再発防止**:
  * 設定画面のような固定レイアウト（スクロール不可画面）では、上部ヘッダー下端からコンテンツ（公式配布員IDカード）までの余白と、下部までの余白を完全に均等（シンメトリー）にする余白設計テンプレートを固定化し、動的な座標操作を禁止する。

### 1.2 初回キャッシュ問題 (Initial Cache Sticky Incident)
* **事象**: `style.css` や `app.js` を修正してデプロイしたにもかかわらず、LINEアプリ内ブラウザ（WebView）で開くと古いコードが実行され、修正が反映されない。
* **原因**: 
  * LINEアプリ内WebViewのキャッシュ機構が極めて強力であり、ブラウザ側のリロードボタンがないため古いアセットを強制的に読み込み続ける。
  * Service Worker (`service-worker.js`) が古いファイルをキャッシュし続けた。
* **対策**:
  * 静的ファイル参照パスの末尾にキャッシュバスターパラメータ（`?v=70` 等）を付与。
  * バージョン番号の管理を自動化し、デプロイ時にHTML内のアセット参照タグのクエリ文字列を自動で現在日時に更新する仕組みを構築。
* **再発防止**:
  * Git commit フックにより、アセットファイル（`app.js`, `style.css`等）に変更が入った場合は、`tools/asset_version_manager.py` がHTMLファイルの参照クエリを自動更新して強制リロードさせる運用ルールを徹底する。

### 1.3 大量データ読込遅延問題 (Large Data Loading Incident)
* **事象**: 配布実績データが数千件を超えた際、アプリ起動時の読み込みローディングが3秒〜10秒以上かかり、タイムアウトやブラウザクラッシュを引き起こす。
* **原因**:
  * アプリ起動時にGoogleスプレッドシートの「全レコード」を一斉にフェッチしていた。
  * 配布員が現場で見る必要のない過去数ヶ月分のログまで同期取得していた。
* **対策**:
  * データのLazy Load（遅延読み込み）を採用。直近の配布データのみを初期ロードし、過去ログは「過去履歴」ページを開いたタイミングで初めてAPIコールを行う分割設計に修正。
  * サーバサイド（GAS）に「サマリー（集計）」シートを設け、起動時はサマリーデータのみを1回で取得するようAPIを整理。
* **再発防止**:
  * 全シート走査APIの禁止。初期ロードAPIのデータサイズ制限を設定し、起動シーケンスで叩くAPIは `getSummary()` に一本化する。

### 1.4 LIFFとChromeの挙動差 (Environment Gap Incident)
* **事象**: Chromeのデベロッパーツール（モバイルエミュレータ）では完璧に動作・レイアウト表示されていたボタンや余白が、LINE LIFF実機で開くと位置がずれたり、タップしても反応しなかったりする。
* **原因**:
  * LINEアプリ内ブラウザ固有のヘッダーバー（閉じるボタンやタイトルバー）およびフッターツールバーが画面占有面積を動的に変化させるため、CSSの `100vh` が実際より大きく計算されて要素が画面外に見切れる。
  * `backdrop-filter: blur` などのCSSプロパティが、一部の古いAndroid OSやLINE内ブラウザで正しくレンダリングされず、デザインが崩れる。
* **対策**:
  * ボトムナビ等の固定レイアウトには `h-[90px]` など明確な高さを指定し、親要素には `h-[100dvh]` を指定。
  * `backdrop-filter: blur` の記述には、必ず Safari/LINE対応用の `-webkit-backdrop-filter` も併記する。
* **再発防止**:
  * 「ブラウザで動く ≠ LIFFで動く」を開発大原則とし、Chromeでのエミュレート検証完了後に、必ずLINE Developersのテストアカウントを用いた実機動作テスト（LINEアプリから起動）をリリース判定フローに組み込む。

### 1.5 Google Sheets大量取得・APIリミット問題 (GAS Sheets API Quota Incident)
* **事象**: アクティブ配布員数が数十人に達した時間帯に、Google Apps Script側で `Exceeded maximum execution time` または `Service error: Spreadsheets` が多発し、APIが応答を停止する。
* **原因**:
  * ループ処理の中でスプレッドシートの `getLastRow()` や `getValue()` などのAPIを何十回も呼び出していた。
  * 読み込み頻度の高い静的マスタデータ（エリア定義など）を、APIリクエストのたびに都度スプレッドシートから読み出していた。
* **対策**:
  * スプレッドシートへのアクセスをバルク処理（`getValues()` で一括配列取得）に統一し、メモリ上でループ処理を行うように修正。
  * GASの `CacheService` を活用し、スプレッドシートから読み込んだマスタデータを一定時間（例: 10分間）メモリキャッシュに保持して Sheets API コールを回避。
* **再発防止**:
  * GASコード内での「ループ内の `SpreadsheetApp` 呼び出し」および「`getLastRow()` の重複コール」を静的解析でエラーとする。

### 1.6 初回Bootstrapクラッシュ (Initial Bootstrap Fail Incident)
* **事象**: 新しい配布員が初めてLINEログインしてアプリを起動した際、白画面のまま進行しなくなる。
* **原因**:
  * 初回起動時にスプレッドシート側に当該ユーザーのレコード（ユーザーマスタ）が存在しない場合のエラーハンドリングが不十分で、JSが例外をスローしてその後の初期化処理（`liff.ready()` 以降）が中断された。
* **対策**:
  * アプリ起動時の初期APIレスポンスが空（新規ユーザー）の場合、自動的にデフォルト値でユーザー登録（サインアップ）APIを叩き、マスタを自動生成してからメイン画面を描画するフォールバックロジックを追加。
* **再発防止**:
  * データが「0件」または「存在しない（Null/Undefined）」の極限エッジケースを必ず初期テストケースに含め、JavaScriptエラーで起動処理が完全にストップしないよう例外のグローバルキャッチを仕込む。

## 2. LIFF開発ベストプラクティス (Best Practices)

### 2.1 LIFF初期化フローの決定論的制御
LIFFアプリは必ず以下の順序で非同期処理を完了させ、確実に準備が整ってからUIを描画する必要があります。

```javascript
window.onload = function() {
  // 1. LIFF IDによる初期化
  liff.init({ liffId: CONFIG.LIFF_ID })
    .then(() => {
      // 2. LIFF準備完了待機
      return liff.ready;
    })
    .then(() => {
      // 3. ログイン状態の確認
      if (!liff.isLoggedIn()) {
        liff.login(); // ログインしていない場合はLINEログイン画面へ強制リダイレクト
        return;
      }
      // 4. ユーザープロファイル・アクセストークンの取得
      const profile = liff.getDecodedIDToken();
      const userId = profile.sub; // LINEの一意なユーザーID
      
      // 5. バックエンド（GAS）から初期サマリーデータをフェッチ
      return initializeApp(userId);
    })
    .then(() => {
      // 6. UIのローディング表示をフェードアウトし、メインコンテンツをフェードイン
      renderApp();
    })
    .catch((error) => {
      showGlobalError("システムの初期化に失敗しました", error);
    });
};
```

### 2.2 強力なキャッシュ対策（アセットバージョン管理）
* `app.js`、`render.js` などのJavaScriptファイルを変更した際は、必ず `index.html` に読み込んでいるタグのパラメータを手動または自動でインクリメントします。
  * `src="app.js?v=202607051200"`
* LINEアプリのトーク画面からLIFFを閉じて再度開く操作ではキャッシュがクリアされないため、動作検証時は「LINEアプリをタスクキルして再起動」するか、テスト用URLのキャッシュバスター値を更新して動作確認を行います。
