## 1. Development Principles (開発原則)

本プラットフォームの開発、保守、およびAIOSのコード生成プロセスにおいては、以下の開発原則を絶対的な憲法として順守します。

### 1.1 ブラウザで動く ≠ LIFFで動く
* **ルール**: PCやモバイルブラウザのエミュレータ上で動作することは、LINE LIFF上での正常動作を保証しません。AIエージェントはブラウザ前提の設計・コード提案に陥りやすいため、変更適用後は**必ず「LIFF実機による検証」を必須工程**とします。

### 1.2 Dashboardは入力画面ではない
* **ルール**: Dashboardはデータを入力・編集するための画面ではなく、現場データを綺麗に見せるための「魅せる商品」として設計します。複雑な入力フォームや設定の構築を避け、直感的なダッシュボードに徹します。

### 1.3 循環モデルの役割分担
* **ルール**: プラットフォーム内の各モジュールは以下の明確な役割境界を守ります。
  * **スマホアプリ (POSTING MAP)**: 現場データの生成 (Data Creator)
  * **Dashboard (PC)**: データの視覚化と意思決定支援 (Data Showcase)
  * **SNS / 営業**: 顧客獲得とサブスク契約拡大 (Sales Engine)

### 1.4 ブラックボックス化
* **ルール**: 本システムは高級政治DXプラットフォームであり、裏で動作しているテクノロジー（Google Sheets, GAS, GitHub等）の存在を利用者（決裁者および配布員）に一切意識させない、完璧なブラックボックスとして構築します。

### 1.5 価格モデルの順守
* **ルール**: 人数に応じた課金制は導入せず、システムが管理する「データ量」（配布ユニット数）に応じた従量見積もりをベースとした設計とします。

### 1.6 「3秒ルール」の適用
* **ルール**: Dashboardのすべてのグラフィック表示、状況確認画面において、「3秒以内に全体の状況が脳に伝わるか」を絶対的なUI/UX基準とします。

## 2. Chrome 検証フロー (Chrome Validation Protocol)

開発段階における品質検証は、以下のChrome DevToolsを用いた監査プロセスを通過したのち、LIFF実機確認へ移行します。

1. **Console解析**: JavaScriptエラー、警告、不要なログ出力の完全な排除。
2. **Network解析**:
   * APIコールの重複排除。
   * GAS/Spreadsheetアクセスの最小化（まとめ取得、Lazy Loadの順守）。
3. **Performance解析**:
   * 初期ロード1秒以内、全体表示3秒以内の高速表示検証。
   * ガクつき（レイアウトシフト）やチラつきの排除。

## 3. Validation OS / AIOS 構想

AIOSは単なるソースコード自動生成に留まらず、設計からビジネス展開までを一気通貫で支援・自動化するインテリジェントオペレーティングシステムを目指します。

```
[Design] ──> [Development] ──> [Validation] ──> [Operation] ──> [Business]
```

### 3.1 Validation OS（自動検証基盤）構想
AIOSの検証レイヤーとして、以下のステップを自律的にループ実行する「Validation OS」を設計します。
* **自動起動**: Chrome等のブラウザ環境をヘッドレス/有頭で起動し、対象ページへ自動遷移。
* **ログ解析**: ブラウザのConsole/Network出力をリアルタイムにインターセプト。
* **自動修正＆再実行**: 検出されたJSエラーやパフォーマンス上のボトルネックをAI自身でその場で修正し、ビルド・再検証を回す自己修復ループ。
* **実機検証へのトランスファー**: Webテストで合格したビルドを自動的にLIFF検証環境へ展開し、実機チェックを促す。

## 4. 開発優先順位 (Development Roadmap)

プロダクト開発は、以下のロードマップに沿って段階的に拡張されます。

| フェーズ | 対象スコープ | 主なマイルストーン |
|---|---|---|
| **Phase 1** | POSTING MAP ＋ 支部Dashboard | 基本機能の完成と三重のファースト案件（MIE-03）適用 |
| **Phase 2** | LIFF品質向上 | 実機におけるネイティブ級UX・表示速度の極限化 |
| **Phase 3** | AIOS Validation機能 | Validation OS（自動Chrome検証・自己修復）の実装 |
| **Phase 4** | 県連Dashboard | 複数支部の集計およびデータ連携の構築 |
| **Phase 5** | ブロックDashboard | ブロック単位の広域アグリゲーション |
| **Phase 6** | 本部Dashboard | 全国ブロックをカバーする統括インフラ |
| **Phase 7** | SNS営業モデル | DashboardとSNSをシームレスに繋ぐマーケティング自動化 |
| **Phase 8** | 他業種展開 | 選挙以外のフィールドオペレーション（戸別配送、地域調査等）への応用 |
