# Decision Log: LIFF Verification Policy & Implementation Gaps

**Date**: 2026-07-05  
**Author**: 岩佐CEO / AI品質管理部  
**Status**: Decided

---

## 1. 決定事項 (Decision)
**「ブラウザで動く ≠ LIFFで動く」**を開発・リリースの基本原則とする。AIおよび人間開発者は、PCブラウザ（Chrome等）の検証に合格後、必ず「LINE LIFF実機（iOS/AndroidのLINEアプリから起動）」による最終動作・レイアウト検証を必須工程とする。

## 2. 理由 (Rationale)
* **強力なキャッシュ機構**: LINEアプリ内ブラウザはキャッシュの保持が極めて強く、一般的なブラウザのように簡単にはリロードできないため、通常のデプロイだけでは古いコードが残りバグを引き起こす。
* **描画領域の動的変動**: LINEのヘッダーバーやシステムのボトムバーにより、実際の画面占有領域はPCエミュレータ上の値と大きく異なる。これにより、レイアウト崩れやボタン押下不可が発生しやすい。
* **WebViewとセキュリティの制限**: リダイレクトや `liff.init()` 前の非同期通信など、LINE内WebView特有のセキュリティ仕様によって発生する「画面真っ黒問題」や「ログイン無限ループ」を防ぐため。

## 3. 採用案 (Alternative Selected)
* デプロイ時には必ずクエリパラメータ（`?v=YYYYMMDDHHMMSS`）を用いたキャッシュバスターを適用する。
* 実機WebViewによる、IDカード等の「余白シンメトリー」「スクロール不具合」の手動確認チェックを最終ゲートとする。

## 4. 却下案 (Alternative Rejected)
* Chromeのデベロッパーツール（モバイルビュー）のみの確認で本番品質とし、デプロイを行う運用。

## 5. 将来見直す条件 (Review Criteria)
* LINE社公式から、LINE内WebViewの強力なキャッシュを無効化するテスト環境、または完璧な再現性を持つPC用シミュレーターが提供され、実機とPCの検証ギャップが完全に解消された場合。
