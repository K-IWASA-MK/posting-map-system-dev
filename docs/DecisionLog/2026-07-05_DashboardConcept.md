# Decision Log: Dashboard Concept & UX Focus

**Date**: 2026-07-05  
**Author**: 岩佐CEO / AI品質管理部  
**Status**: Decided

---

## 1. 決定事項 (Decision)
Dashboardは「細かなデータの管理・入力画面」ではなく、スマホアプリが生成したデータを視覚的に提示して意思決定を支援する**「魅せる商品（Showcase）」**として設計する。

## 2. 理由 (Rationale)
* **意思決定の迅速化**: 決裁者（支部長や候補者）が必要としているのは、スプレッドシートのような細かなデータ一覧ではなく、「今日、誰が、どこを配ったか」が瞬時に理解できる視覚的アウトプットである。
* **営業・デモ効果の最大化**: サブスクリプション契約を獲得するための強力なフック（SNSや直接営業時）として、PCで開いた瞬間に「おおっ」と惹きつける高級感あるUI/UXが必須となるため。
* **役割の分離**: スマホアプリ（データ入力）とPC（データ可視化）で責務を明確に分けることで、両画面のUI設計を極限までシンプルに保つことができる。

## 3. 採用案 (Alternative Selected)
* 「3秒で状況が伝わるUI」を絶対的な設計基準とする。
* スクロールを最小化し、ファーストビューで主要情報が完結するレイアウト。
* 漆黒背景（#000000 / #1C1C1E）と青・緑の発光アクセントを採用。

## 4. 却下案 (Alternative Rejected)
* Google Sheetsのような多機能グリッド（表形式）でのデータ修正・入力・設定が混在する複雑なDashboard。
* 多数の設定ボタンやフィルタリング項目が存在し、操作にITリテラシーを要求するUI。

## 5. 将来見直す条件 (Review Criteria)
* 支部から県連・ブロック・本部へと Dashboard 階層が拡張される過程で、単純な1画面可視化では表現しきれない組織統制上必要な入力（例：支部の割当管理など）がどうしても発生した場合。
