# GPT Memory Log - 2026-07-06

## 📍 1. 設計判断・合意事項 (Design Decisions)
本日決定されたプロダクト仕様および設計方針のまとめです。

### ① GPS仕様の簡素化
- 画面上に `徒歩5分` `車8分` `○km` などの距離情報は**表示しない (❌)**。
- GPSの用途は以下に限定する：
  1. LIFF起動時の現在地取得
  2. 初期表示時の市町村の初期選択
  3. 活動終了時の活動記録
- **活動終了フロー**:
  配布員が `活動終了・枚数入力` ➔ `GPS取得（1回のみ実行）` ➔ `写真撮影` ➔ `保存・送信`。

### ② 写真撮影の目的と扱い
- 目的は「手抜き監視」や「証拠提出」ではない。配布員自身の「自己報告」「達成感」「次回への活動意欲向上」のために活用する。
- ダッシュボード（管理者側）には写真は**一切表示しない**。
- 写真データは Google Drive 等の外部ストレージへ直接保存し、**30日後に自動削除**する。

### ③ Dashboard の活動ログ中心設計
- ダッシュボードのコアは**「活動ログ（時系列のリスト表示）」**である。
  ```text
  [活動ログの基本レイアウト例]
  --------------------------------------------------
  2026/07/06 09:15 | 鈴鹿市 | S025 | 300枚配布
  --------------------------------------------------
  2026/07/06 10:42 | 鈴鹿市 | S008 | 500枚配布
  --------------------------------------------------
  ```
- グラフ表示や進捗分析は、この活動ログリストを美しく魅せるための「演出」として位置付ける。

### ④ Dashboardの静と動のコントラスト設計 (Live Operations Dashboard Rules)
- **全体レイアウト**: `height: 100vh; overflow: hidden;` をベースとし、ダッシュボード外枠は絶対にスクロールせず不動。動くのは「活動ログ」と「保管者一覧」のリスト内側のみ。
- **「動くべきものだけを動かす」原則 (静と動の対比)**:
  1. **新着ログ (タイムライン)**: 一番上にスッと入って最上部に「NEW」バッジを表示。同時にカード境界が一時的（3秒）にオレンジネオンに発光し、5秒後にバッジと発光が消えて静的なカードに同化する。
  2. **ローリングナンバー**: KPIカードや保管者リストの数値更新時は、数字がドラムのように回転して滑らかに増減する（Odometer効果）。
  3. **保管者リストのチラシ変動**: 配布員への受渡等で枚数が減った瞬間、その保管者カードが一瞬だけオレンジに発光し、数値がローリングする（「今ここでチラシが動いた」というオペレーションの実感を管理者に与える）。
  4. **グラフの更新**: 毎秒動かすのではなく、5〜10秒ごとの穏やかな間隔で滑らかに更新する。
  5. **LIVEインジケータ**: 激しい点滅はノイズになるため却下。呼吸するように極めてゆっくりと明滅（● ➔ ○ ➔ ●）させる。
