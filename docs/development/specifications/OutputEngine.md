# 出力制御エンジン仕様書 (Output Engine Specification)

## 目的
AIOS（品質保証オペレーティングシステム）におけるすべての出力品質を統一する。本エンジンは、AIの知識そのものではなく、AIから出力される表現、言語、構成、フォーマットを決定論的に制御するOSレイヤーである。

## 責務
AIOSがユーザー（岩佐CEO）へ提示する以下のすべての出力形式を統一する。
- 実装計画書
- レビュー結果
- 実装完了報告
- 実績説明書 (Walkthrough)
- コミット報告 (Commit)
- プッシュ報告 (Push)
- エラー報告
- 改善提案

## 出力原則 (Rules)

### 規則001 (Rule 001): 日本語の標準化
- 日本語を標準言語とする。
- 英語タイトルおよび英語見出しは一切禁止する。
- 英語UI用語（例: HTML, CSS, JavaScript, API等）などの技術的固有名詞を除き、日本語の表現を最優先する。

### 規則002 (Rule 002): CEOファースト記述
- ユーザー（岩佐CEO）がそのまま読める文章構成にする。
- AI内部向けの技術的な説明やモデル向けの説明、冗長な前置きは一切排除する。

### 規則003 (Rule 003): コピー可能な単一構造
- 実装計画書は、以下の項目と順番のみで構成する。これ以外の項目追加や順序変更は禁止する。
  1. `# 実装計画` (大見出し)
  2. `目的` (中見出しまたは太字)
  3. `変更内容` (中見出しまたは太字)
  4. `対象ファイル` (中見出しまたは太字)
  5. `レビュー項目` (中見出しまたは太字)
  6. `Proceed待ち` または `レビュー待ち` (最終行)

### 規則004 (Rule 004): コードブロックの統一
- ドキュメント内のコードや設定などの長文は、必ず「1つのコードブロック」にまとめて出力する。
- 複数のコードブロックに分割して出力することを禁止する。

### 規則005 (Rule 005): チャット直接出力の優先 (Artifact依存の禁止)
- 出力制御エンジンは、以下の構成を基本とする。
  - チャット本文
  - コードブロック
  - 必要最小限のMarkdown
- ユーザーへの報告において、Artifactファイルのみに内容を記述し、チャット本文を空にしたり、省略したりする構成を禁止する。チャット本文へ直接内容を出力する。

### 規則006 (Rule 006): AIOS標準開発フローの順守
- 開発および出力は、以下のステージ順序で進める。
  1. 実装計画書提示
  2. レビュー
  3. Proceed（ユーザー承認）
  4. 実装
  5. 実績説明書 (Walkthrough)
  6. コミット (Commit)
  7. プッシュ (Push)
  8. 完了

### 規則007 (Rule 007): 実績説明書の厳格な構成
- 実績説明書（Walkthrough）は、必ず以下の項目と順番のみで構成する。
  1. `# 実績説明書`
  2. `変更内容`
  3. `変更理由`
  4. `影響範囲`
  5. `検証`
  6. `コミット`

### 規則008 (Rule 008): 不要な英語表現の排除
- 仕様書、計画書、チャット出力におけるヘッダーや項目名において、不要な英語表現を禁止する。
- 以下の対比マッピングを厳守すること。

| 禁止される英語表記 | 推奨される日本語表記 |
|---|---|
| Implementation Plan | 実装計画書 |
| Foundation | 基礎・基盤 |
| Goal | 目的 |
| Review | レビュー |
| Open Questions | 質問事項 / 確認事項 |
| Summary | 要約・まとめ |

### 規則009 (Rule 009): レビュー状態の明示化
- 返答の最終行は、ユーザーの次のアクションを促すため、必ず以下のいずれかの単語で締めくくる。
  - `Proceed待ち`
  - `レビュー待ち`

### 規則010 (Rule 010): OSレベルでの品質保証
- AIモデル（Flash, Proなど）の性能に依存せず、この出力制御エンジン（Output Engine）が最終出力の表記揺れや構成違反を検知・補正し、品質を保証する。
