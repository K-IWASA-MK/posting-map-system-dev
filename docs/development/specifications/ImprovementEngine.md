# 改善エンジン仕様書 (Improvement Engine Specification)

## 目的
AIOS（品質保証オペレーティングシステム）において、自己レビューエンジン（Self Review Engine）の指示に基づき、品質レビューで検出された違反内容やスコア低下の原因に対する具体的なコード・ドキュメントの「改善タスク」および「修正候補案」を生成するエンジンの仕様を定義する。

---

## 責務
- **改善候補生成 (Candidate Generation)**: 検出された問題点（例: AI Smell Level 2）を解消するための具体的な修正コード案（Diff形式）や代替設計の候補を生成。
- **改善理由生成 (Reasoning)**: なぜその修正が必要であるのか、どのルール（例: 第0原則）に基づいているのかの技術的根拠を明確化。
- **優先順位割り当て (Prioritization)**: 改善対象に対して緊急度（Improvement Priority）を設定。
- **対象分類 (Categorization)**: 改善を及ぼす変更範囲（Architecture / UI / GAS / Documentation 等）の識別。

---

## 改善優先順位 (Improvement Priority) 規律
改善タスクには、以下の緊急度・影響度に応じた4段階の優先順位が適用される。

1. **P1 (重大品質問題 - 即改善)**:
   - アーキテクチャ違反（一方向依存の崩壊）、重大な機能欠落、またはセキュリティ・例外エラーを引き起こす問題。リリースブロック対象。
2. **P2 (UX改善 - 優先改善)**:
   - 「第0原則」違反（迷わせる導線）、不自然な視線移動、または生命感（Emotion）の欠如。極力リリース前に改善すべき対象。
3. **P3 (デザイン/出力改善 - 余裕があれば改善)**:
   - TypographyやColor、および日本語表記ルール（Output Engine原則）の部分的な違反。
4. **P4 (Polish - 職人レベルの微調整)**:
   - アニメーションのイージングの微調整、1px単位の余白調整などの最終的な磨き上げ。

---

## 将来の実行フェーズに向けたアーキテクチャ (Future Implementation)
本エンジンは、将来的に以下のプロセスを実行可能な機能構成として拡張される。
- **複数改善案（A/B案）の提示**: 同一の品質問題に対して、アプローチの異なる複数の修正候補コードを生成し、最適なものを自己レビューエンジンが自動選択するロジック。
- **修正依存関係の解消**: 複数のファイルにまたがる修正を実行する際、どのファイルをどのような順序で書き換えるべきかの「実行計画」の作成。
