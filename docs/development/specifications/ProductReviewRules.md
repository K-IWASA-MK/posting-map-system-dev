# プロダクトレビュー規則仕様書 (Product Review Rules Specification)

## 目的
AIOS（品質保証オペレーティングシステム）において、プロダクトの製品品質および利用体験を客観的・構造的にレビュー・評価するための「プロダクトレビュー規則（Product Review Rules）」を定義する。

---

## 評価カテゴリおよびレビュー項目

### 1. 第一印象 (First Impression)
ユーザーが画面を開いた瞬間の「最初の3秒」で、システムの意図と状態を直感的に把握できなければならない。
- **3秒の理解度**:
  - 何を行うための画面かが瞬時に理解できること。
  - 現在のシステム状態（稼働中、接続エラー、未認証など）がテキストを読み込まなくてもビジュアルで判別できること。
  - 最も実行すべき主アクション（プライマリーボタン）が視覚的に際立っていること。

### 2. 視線誘導 (Flow)
画面内の視覚的重心と視線の移動経路が、ユーザーの認知負荷を最小化するように設計されていなければならない。
- **自然な視線移動**:
  - Zパターン（左上から右上、左下から右下）またはFパターン（上から下、左から右）の基本レイアウト規律が守られていること。
  - 視線のジャンプ（脈絡のない視線移動）を引き起こす、非対称な要素配置や突飛な配色の配置がないこと。
  - 項目グループ（Card）間の境界が明瞭で、視覚的階層が論理的に整理されていること。

### 3. 生命感 (Emotion)
システムが単なる静止画ではなく、「リアルタイムで生きている」実感をユーザーに与えなければならない。
- **アクティブ感の演出**:
  - LIVEインジケーターなどのステータス表示には、呼吸するようなゆっくりとした明滅アニメーション（パルス効果）が適用されていること。
  - 数値更新時、突然値が切り替わるのではなく、滑らかなドラムロール（Rolling Number）等のイフェクトが組み込まれていること。
  - 状態遷移時（ページ遷移や読込中）、一瞬の白画面（Flash）やガクつきがなく、フェードイン・アウトが適用されていること。

### 4. 職人品質 (Craftsmanship)
細部の仕上がりが、プロダクト全体の「高級感」と「信頼性」を決定づける。
- **余白設計 (Spacing)**:
  - Appleネイティブアプリ基準の、十分な余白（Padding / Margin）が確保されていること。要素を詰め込みすぎた窮屈なUIを禁止する。
- **フォント規律 (Typography)**:
  - フォントサイズ、ウェイト（太さ）のコントラストが適切に設計され、情報の重要度が文字の大きさで判別できること。標準ブラウザフォントの使用を禁止する。
- **カラーパレット (Color Palette)**:
  - 漆黒（#000000）をベースとし、カード背景は #1C1C1E、枠線は不透明度0.1以下の透過白（rgba(255,255,255,0.1)）に統一されていること。
  - 原色（純粋な赤、青、緑）を排除し、厳選されたアクセントカラー（青: #2563eb、緑: #22c55e）のみが使われていること。
- **イージング (Easing)**:
  - アニメーションはリニア（等速）ではなく、必ず `ease-out` またはカスタムベジェ曲線で定義され、初速が速く最後は静かに減速する自然な物理挙動を模していること。
- **1pxの精度**:
  - すべての境界線、シャドウ、角丸（border-radius: 28px基準）が崩れなく配置され、ズレが生じていないこと。

### 5. ブランド同一性 (Identity)
プロダクトが「初期費用100万円・月額10万円以上」のハイエンド製品としての世界観を維持しなければならない。
- **世界観の統一**:
  - カジュアルなアイコン、安っぽい絵文字の多用、遊びのある表現を排除し、「プロフェッショナルな統制端末」「Mission Control」としての冷徹で高級なインダストリアルデザインを維持していること。
