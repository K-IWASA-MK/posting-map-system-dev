# Dashboard Layout Polish Specification (DashboardLayoutPolish.md)

## 1. Layout Refinement 方針
本仕様は、AIOS Dashboard における視覚表示品質の向上（Polish）を目的とするレイアウト設計指針である。
過剰な装飾や複雑な操作 UI を一切排除し、情報の「整列性」「可読性」「静寂な高級感」を極限まで高めることを目指す。

- **静寂と高級感**: 余白（Apple 級の十分なマージン・パディング）を第一の意匠として扱い、コンテンツ間の息苦しさを排除する。
- **Observer 整合**: 情報はすべて静的に提示され、表示要素自体が状態変更をトリガーするボタンや入力フォーム等のコントロールを持たないこと。

---

## 2. 余白設計の概念 (Layout Spacing Concept)
ダッシュボード全体の骨格レイアウトにおける余白は、以下の階層的定義（Spacing System）に従い制御する。
- **ページ外郭余白 (Page Outer Margins)**: 画面の最端からコンテンツ領域までの余白。モバイル/タブレット/デスクトップに応じて動的にブレイクポイントを制御する。
- **グリッドギャップ (Grid Gap)**: メイングリッドで並ぶ情報カード間の均一な距離。
- **カード内包パディング (Card Internal Padding)**: カード内部の見出し、リスト、メトリクス表示パーツ間の余白。

---

## 3. Grid System & Responsive Rule
ダッシュボードのメインコンテンツ領域はCSSグリッド（`display: grid`）によって可変レイアウトされる。

### グリッドパラメータ
- **最大幅 (Max Width)**: `1200px`（コンテンツ全体の中央揃え）
- **列数と幅の自動調整**: `grid-template-columns: repeat(auto-fill, minmax(320px, 1fr))`

### ブレイクポイントとレスポンシブ挙動
1. **Desktop / Large Screen (> 1024px)**:
   - メイングリッドは 3列 または 2列（`grid-col-2` 指定のカードは2カラム幅を占有）で展開。
   - ページ外郭余白: `32px`
   - グリッドギャップ: `24px`
2. **Tablet / Medium Screen (768px - 1024px)**:
   - メイングリッドは 2列 または 1列で展開。
   - `grid-col-2` カードは自動的に 100% 幅（`grid-column: span 2` が維持されるが、実質全体幅に伸縮）となる。
   - ページ外郭余白: `24px`
   - グリッドギャップ: `20px`
3. **Mobile / Small Screen (< 768px)**:
   - すべてのカードが単一列（1列）に縦積み配置される。
   - ページ外郭余白: `16px`
   - グリッドギャップ: `16px`

## 4. Appleライクな Visual Hierarchy (視覚的階層)
情報を一瞬で理解できるように、強弱と位置関係（コントラスト）を調整する。

- **第1階層: 最上部ヘッダー (Global Environment & Status)**:
  - 画面最上部に固定。文字サイズは控えめにしつつ、Environment（LOCAL SIMULATION 等）やシステム状態（LIVE / OFFLINE）等の「状態定義バッジ」を右上方に配置して最優先で視線誘導する。
- **第2階層: メインKPIカードの見出し (Section Header)**:
  - カードごとに均一なフォントサイズ（`1.1rem`）、セミボルド（`600`）で配置し、ほのかな下線（border-bottom）でコンテンツを区切る。
- **第3階層: メトリクス数値 (Metrics Values)**:
  - スコアや数量など、最も目を引くべき値はフォントサイズ `1.5rem`〜`1.8rem`、太字（`700`）で強調表示する。
- **第4階層: ラベルと補助テキスト (Subtext & Labels)**:
  - 小サイズ（`0.8rem`〜`0.85rem`）、フォントウェイト `500`。不透明度を `0.6`〜`0.72` に下げることで、数値とのコントラスト比を明確にする。
