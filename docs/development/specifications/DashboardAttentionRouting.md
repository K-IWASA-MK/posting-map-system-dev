# Dashboard Attention Routing Specification (DashboardAttentionRouting.md)

## 1. アテンションキュー (Attention Queue) の設計制約
ダッシュボード上にリアルタイムイベントを表示する際、時系列順ではなく「重要度順（CRITICAL ➔ WARNING ➔ INFO）」に整列して表示し、リソースの枯渇や表示崩れを防ぐため、アテンションキュー（`DashboardAttentionQueue`）は以下の動作制約を守る。

- **優先度ソート (Priority Sorting)**:
  新着イベント受信時、キューは以下の順序規則で配列を並び替える。
  1. `severity` が `CRITICAL` のイベント（新しいもの順）
  2. `severity` が `WARNING` のイベント（新しいもの順）
  3. `severity` が `INFO` のイベント（新しいもの順）
- **最大保持数制限 (Capacity Limit)**:
  メモリ上に無限にログが蓄積されてブラウザの動作が重くなるのを防ぐため、キューは最大 `50` 件に件数を制限する。上限超過時は、重要度の低いイベント、同重要度内では古いイベントから順に自動的に破棄（DROP）する。
- **重複排除の担保**:
  アダプター層の重複排除を二重で補強するため、キュー登録時にも `eventId` による一意チェックを行い、重複登録を遮断する。

## 2. 視覚的ルーティング (Visual Routing) と警告制約
重要度に基づいて、ダッシュボード上の適切なコンポーネントおよび表示スタイルへイベントを振り分ける（Visual Routing）。

- **CRITICAL イベントのルーティング**:
  * ログリスト (`ActivityLogCard`) 内で、背景を微赤発色（`.log-critical`）させて最上位に表示。
  * `StatusCard` およびヘッダーのステータス表示を、一時的に `DashboardMotion.glowCard` を用いて強く青発光（Glow）させて管理者に警告。
- **WARNING イベントのルーティング**:
  * ログリスト内で、黄色い左境界線（`.log-warning`）を付与して強調。
  * `ActivityLogCard` 自体を一時的に Glow 演出させて警告。
- **INFO イベントのルーティング**:
  * ログリスト内に通常のスタイル（フェードインのみ）で挿入。

### 🚨 自動アクション・通知等の絶対禁止
本ダッシュボードは「Observer（観測装置）」であるため、どれだけ重大な `CRITICAL` イベントを受信した場合であっても、以下の自動アクションを実行することは構造上・規約上一切禁止する。
* **音声アラームの再生**: 管理者の注意を惹く目的であっても、ブラウザからの音声警告等の再生は禁止。
* **プッシュ通知・電子メール・チャット連携の自動送信**: ダッシュボード層から直接外部への Webhook や LINE / Slack 通知、メールを送信することは一切禁止する（通知送信は Kernel/バックエンドの職務である）。
* **自動コマンド・自動承認**: イベント契機で他のカーネル API に対して実行や承認のシグナルを逆流送信してはならない。
