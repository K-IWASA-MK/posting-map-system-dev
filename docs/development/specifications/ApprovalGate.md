# 承認ゲート仕様書 (Approval Gate Specification)

## 目的
AIOS（品質保証オペレーティングシステム）において、システム全体のガバナンスポリシーや重要ルールの変更、およびナレッジのライフサイクル昇格（Promotion）や統合（Merge）を人間の直接統制下に置くための「ヒューマン承認ゲート（Human Approval Gate）」の状態モデルおよび制御ルールを定義する。

---

## 承認必須項目 (Approval Scope)
以下の重大アクションに対しては、ガバナンスエンジンは必ずヒューマン承認ゲートを起動し、承認保留（Pending）としなければならない。

1. **ナレッジの公式昇格 (Knowledge Promotion)**:
   - ナレッジの成熟度を `Official` へ昇格させるアクション。
2. **ナレッジの統合実行 (Knowledge Merge)**:
   - 最適化エンジンが提示した統合候補（Merge Candidates）を、実際に適用するアクション。
3. **ポリシー変更 (Policy Change)**:
   - ガバナンスポリシー仕様書、または関連するデータスキーマ定義を変更するアクション。
4. **重大ルールの変更 (Critical Rule Change)**:
   - 重大度（Severity）が `Blocker` であるガバナンスルール定義の追加・削除・変更を行うアクション。

---

## 承認ゲート状態モデル (Approval Status Model)
承認ゲートは、以下の状態（Status）を決定論的に管理する。**AIモデルによる自動的な状態更新は厳重に禁止する。**

```
[起案検知] ──> [Pending (承認待ち保留)] ──┬──(人間の承認)──> [Approved (承認完了)]
                                           ├──(人間の却下)──> [Rejected (却下完了)]
                                           └──(期間超過)────> [Expired (期限切れ無効)]
```

- **Pending (保留)**:
  - 承認要求が生成され、人間（管理者）の直接操作を待っている状態。後続の実行エンジンへの処理移管はブロックされる。
- **Approved (承認)**:
  - 管理者（岩佐CEO等）によって、内容の安全性が公式に確認され、実行許可が与えられた状態。
- **Rejected (却下)**:
  - 管理者によって実行が不適合と判断された状態。起案された変更や統合計画は即時破棄または差し戻される。
- **Expired (期限切れ)**:
  - 一定期間（例: 7日間）承認アクションが行われなかったため、安全のため自動的に無効化された状態。

---

## 自動承認禁止ルール (No Self-Approval Rule)
- **AI自動承認の絶対禁止**:
  - 承認状態の `Pending` から `Approved` への遷移は、**管理者の手動UI操作またはデジタル署名によってのみ実行可能**とする。
  - AI自身が承認 API を直接叩くこと、またはコード定義の上書きによって承認ゲートをバイパス（Bypass）することをシステムレベルで完全に禁止する。
- **フォールバック経路の禁止**:
  - 管理者の未応答時に自動的に `Approved` にするような、人間の介入を省略する「Fallback Approved」ロジックの設計・実装を一切禁止する。
