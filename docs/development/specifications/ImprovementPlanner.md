# 改善プランナー仕様書 (Improvement Planner Specification)

## 目的
AIOS（品質保証オペレーティングシステム）において、品質スコアエンジンから出力された問題データ（P1〜P4）を解析し、システムへの影響度や依存関係を考慮した安全かつ極小化された「改善タスク計画」を自動立案する「改善プランナー（Improvement Planner）」の仕様を定義する。

---

## 責務
- **改善対象抽出**: どのモジュール・ファイルが品質低下の主因となっているかを特定。
- **改善優先順位の分析**: スコアデータの Priority に基づいて、修正着手の順番を並べ替え。
- **改善単位分割 (Task Splitting)**: 
  - 改善を肥大化させず、**「1タスク ＝ 1つの明確な責務（1 Task = 1 Responsibility）」**の単位に最小分割。
- **依存関係解析 (Dependency Resolution)**: 修正対象ファイル間の静的・動的依存関係を解析。
- **リスク評価 (Risk Assessment)**: 提案される改善がシステムに与える影響リスクを判定。
- **改善順序決定**: 依存関係で先んじて変更されるべきファイル（依存される側）を上位にする、トポロジカルソート等の順序決定。

---

## リスク評価 (Risk Assessment) 規律
プランナーは、作成された各改善タスクに対して、以下のリスクレベルを評価・付与しなければならない。これは自動実行の可否決定に直結する。

| リスクレベル | 判定対象の例 | 制御方針 |
|---|---|---|
| **Low (低リスク)** | UIや表記の微調整、軽微なドキュメントの修正、Typographyや色の値のみの変更など。 | テストおよび検証ステージが PASS すれば、人間の承認を挟まず自動実行が可能。 |
| **Medium (中リスク)** | UIコンポーネントの内部ロジック変更、スタイルクラスの再配置、またはGAS側のローカルヘルパー関数の変更など。 | 実行時レビュー（Runtime Review）の検証結果に基づく条件付き自動実行。 |
| **High (高リスク)** | レイヤー分離をまたぐ変更、Spreadsheetスキーマの変更、APIゲートウェイのインターフェース変更など。 | **自動実行を禁止。** 人間の承認（Human Approval）ゲートへのエスカレーションを必須とする。 |

---

## 改善計画のデータ構造 (Plan Data Structure)
改善プランナーが生成する計画オブジェクトの論理構造。

```json
{
  "planId": "PLN-2026-0001",
  "reviewId": "REV-2026-0422",
  "strategy": "Balanced",
  "tasks": [
    {
      "taskId": "TSK-001",
      "responsibility": "ボトムナビの配色コントラスト改善",
      "targetFile": "tailwind-utils.css",
      "priority": "P2",
      "risk": "Low",
      "dependencies": []
    },
    {
      "taskId": "TSK-002",
      "responsibility": "GASレスポンスJSON構造の検証処理追加",
      "targetFile": "db.js",
      "priority": "P1",
      "risk": "High",
      "dependencies": ["TSK-001"]
    }
  ]
}
```
