# Dashboard Accessibility Specification (DashboardAccessibility.md)

## 1. 目的と基本方針
本仕様は、AIOS Dashboard におけるアクセシビリティ（Accessibility / a11y）対応方針を定義する。
ダッシュボードは「表示・観測専用レイヤー（Observer）」であるため、キーボードや音声読み上げで「情報が正確に伝わること」に特化する。
不要な操作用フォーカスや入力エラーなどの混乱要素を排除し、静的なデータの明瞭な提示を徹底する。

---

## 2. 色覚多様性対応 (Color Accessibility)
色だけに頼ってステータスや情報を伝えないためのカラー設計。
- **インジケーターの多重表現**: 
  ステータス表示（LIVE/OFFLINE, PASS/FAIL）では、色（緑・赤等）の変更だけでなく、文字ラベル（LIVE / OFFLINE, PASS / FAIL等）を併記する。また、グラフなどのビジュアル要素でも形状（データポイントの形状や枠線の太さ）で区別できるようにする。
- **色相・明度の調整**: 色盲（赤緑色盲など）のユーザーでも判別可能なように、緑（`#22c55e`）や橙（`#ea580c`）、赤（`#ef4444`）の輝度・彩度のコントラストを調整して識別性を向上させる。

---

## 3. コントラスト比基準 (Contrast Ratio Standards)
WCAG 2.1 AA 基準に準拠したテキストコントラスト比を確保する。
- **通常テキスト (18px / 1.125rem 未満)**: 背景とのコントラスト比 4.5:1 以上。
- **太字または大テキスト (18px / 1.125rem 以上)**: コントラスト比 3:1 以上。
- **境界線・アイコン等の非テキスト要素**: コントラスト比 3:1 以上。
- **ダークテーマでの調整**: 純黒（`#000000`）背景において、明灰のテキスト（`rgba(255,255,255,0.72)` 以上）やアクセント青（`#2563eb`）のコントラストを最適化し、暗所でも文字が滲まない輝度を選択する。

---

## 4. フォーカス不可領域設計 (Focus Exclusion Design)
表示専用であるダッシュボードのナビゲーション特性。
- **避けるべき属性**: `role="button"`, `role="textbox"` など、操作UIとしてユーザーに誤認させる恐れのある属性は絶対に使用しない。
- **不必要な Tab キーフォーカス排除**: 
  カードやメトリクス数値、静的ログリストは読み取り専用であるため、Tab キーでのフォーカス移動（`tabindex`）は与えない。ナビゲーション用のサイドバーリンク等の必要な要素にのみ適正なフォーカスを当てる。

---

## 5. スクリーンリーダー対応 (Screen Reader & WAI-ARIA)
音声読み上げブラウザでの解釈の最適化。
- **ランドマークの明示**: 支援技術が画面構造を把握しやすいよう、ヘッダーに `role="banner"`、サイドバーに `role="navigation"`、メイングリッドに `role="main"` を明記する。
- **新着ログのリアルタイム通知 (aria-live)**:
  システムログがリアルタイムに Prepend 挿入された場合、`aria-live="polite"`（または `role="status"`）を指定したコンテナを用いて、読み上げ中のコンテンツを遮らずに新着ログを自然にアナウンスさせる。
- **詳細説明属性の適用**:
  各カードや指標セクションには `aria-label="[コンポーネント名]"` などの説明的属性を付与し、何のメトリクスを表示しているかを明確にする。装飾用の SVG アイコン等には `aria-hidden="true"` を適用し、読み上げをバイパスする。
