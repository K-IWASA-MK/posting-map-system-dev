# Dashboard Responsive Layout Specification (DashboardResponsive.md)

## 1. 目的とレスポンシブ方針
本仕様は、AIOS Dashboard における複数デバイス表示の最適化（Responsive Layout）を定義する。
大画面のデスクトップ環境から、タブレット、スマートフォンなどのモバイル環境まで、あらゆる画面幅で「情報が重ならず、見切れず、横スクロールを発生させない」強牢な流動レイアウトを構築する。

---

## 2. ブレイクポイント定義 (Breakpoint Map)

ダッシュボードは、画面幅（ビューポート）に応じて以下の4つのブレイクポイントでアスペクト比およびカラム配置を可変とする。

| 分類 | ビューポート幅 | グリッド配置 (Main Grid) | サイドバー挙動 | 外郭余白 |
|---|---|---|---|---|
| **Large Desktop** | `1440px` 以上 | 3列または4列で展開 (`max-width: 1400px` 固定表示) | 左側固定表示 (幅 240px) | `32px` |
| **Desktop** | `1024px` 〜 `1439px` | 3列で展開 (幅に応じて伸縮) | 左側固定表示 (幅 240px) | `24px` |
| **Tablet** | `768px` 〜 `1023px` | 2列または1列で展開。`grid-col-2` カードは 100% 幅に。 | 左側固定表示、または画面上部/下部へフレックス再配置。 | `20px` |
| **Small Screen (Mobile)**| `767px` 以下 | 1列（縦積み）に再配置。すべてのカードが 100% 幅。 | モバイル下部にフレックス配置（ナビゲーションタブ化）。※操作トグルボタンの追加は禁止。 | `16px` |

---

## 3. 流動タイポグラフィとコンポーネントの調整

- **タイポグラフィのスケーリング (Fluid Typography)**:
  `font-size` やカード内の `padding` には `clamp()` 関数を活用し、画面幅の縮小に応じて文字サイズが滑らかにスケールダウンするように制御する。
  - 例: `font-size: clamp(1.2rem, 2.5vw, 1.8rem)` などの記述で折り返し崩れを防ぐ。
- **テキストオーバーフロー対策**:
  都市名や長文のステータスメッセージが含まれる領域（`TurnoutProgressBar` や `ActivityLogCard` 等）では、文字が見切れないよう、適切な折り返し定義（`word-break: break-all`）または省略符号化（`text-overflow: ellipsis; white-space: nowrap; overflow: hidden;`）を施す。
- **カードの最小幅 (Minimum Width)**:
  極端に画面が細くなった場合でもカードの輪郭が潰れないよう、各カードに `min-width: 280px` を担保する。

---

## 4. サイドバー・ナビゲーションのレスポンシブ制約

### モバイル対応時における折りたたみ（Collapse）規則
- **操作用トグルボタン追加の絶対禁止**:
  サイドバーを折りたたむための開閉トグルボタンや、ハンバーガーメニューのような「状態保持が必要な操作 UI」は一切追加しない。
- **レイアウトレベルでの再配置（Flex layout change）**:
  画面幅が `Small Screen (Mobile)` に切り替わった際、サイドバーは CSS メディアクエリの制御のみによって、画面最下部へのフレックス配置（ボトムナビゲーションまたはフッター的な横並びタブバー）へ自動的に再配置される。
  - 表示順やフォーカスの順序が論理的に連続するように配置を維持する。
