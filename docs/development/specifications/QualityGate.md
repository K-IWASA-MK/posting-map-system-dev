# 品質ゲート仕様書 (Quality Gate Specification)

## 目的
AIOS（品質保証オペレーティングシステム）において、コードのコミットやリリース（デプロイ）を許可するかを決定論的に自動判断する「品質ゲート（Quality Gate）」の評価基準、合格条件、および不合格判定の処置について規定する。

---

## 評価判定基準 (Gate Criteria)

### 1. 合格条件 (PASS Conditions)
品質ゲートが「合格（PASS）」と判定し、変更を許可するためには、以下の項目すべてを満たさなければならない。

- **接続契約アサーションの合格 (Contract Test PASS)**:
  - レイヤー間データ受け渡し接続試験において、接続契約違反（必須キー不足、型不適合）が 0 件であること。
- **シナリオ実行の正常稼働 (Scenario Test PASS)**:
  - 定義済みのすべての回帰シナリオ（正常・異常・承認ゲート）が、想定された期待結果（Expected Result）通りに機能し終えること。
- **本番環境隔離の完全充足 (Boundary Test PASS)**:
  - シミュレーションコードおよびテストコード内に、本番環境干渉（`SpreadsheetApp`、Stripe API、実データベース等）への依存経路・参照が一切存在しないこと。
- **監査ログ記録の整合 (Audit Validity)**:
  - テスト実行中の監査イベントログがすべて追記のみ（Append-Only）で不整合なく保存されていること。

### 2. 不合格条件 (FAIL Conditions)
以下のいずれか 1 項目でも検知された場合、品質ゲートは即座に「不合格（FAIL）」と判定し、変更を却下（Block）する。

- **スキーマの破壊 (Schema Mismatch)**:
  - 既存モジュールの変更によって、後段レイヤーで必須なフィールドが消去、または型が書き換えられた場合。
- **隔離境界の侵害 (Isolation Leak)**:
  - シミュレーション/テストコード内に本番 SDK または API への干渉コードの import 参照が検知された場合。
- **監査不整合 (Audit Fail)**:
  - 監査ログファイルの書き込みエラー、または上書き（Update）・削除（Delete）処理の企てが検知された場合。
